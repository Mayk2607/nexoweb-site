## Clasificación de hallazgos (15 total)

### P0 — Bloqueadores críticos para Go Live

#### P0-001 — Discrepancia rutas nginx/rsync
**Estado:** FALSO POSITIVO (confirmado en WEB-003)

- **Reporte inicial:** Nginx config tiene `alias /var/www/assets/` pero el script `sync-assets-to-vps.sh` sincroniza a `/var/www/nexoweb-assets/`. Aparente mismatch que impediría servir assets.
- **Resolución WEB-003:** El docker-compose.yml del servicio nginx define volume mount:
  ```yaml
  volumes:
    - /var/www/nexoweb-assets:/var/www/assets:ro
  ```
  Este mount es el puente intencional entre la ruta del host y la ruta del contenedor. No hay discrepancia.

---

#### P0-002 — Secretos hardcodeados en docker-compose.yml
**Estado:** CONFIRMADO — REAL — Resuelto en WEB-003

**Archivo:** `crm-nexoweb/docker-compose.yml`

**Evidencia exacta del problema:**

```yaml
# backend service — línea ~24 (antes del fix)
- PUBLIC_LEADS_INGEST_SECRET=<SECRETO ROTADO -- ver WEB-004, valor invalidado y verificado operativamente el 2026-07-24>

# landing service — línea ~61 (antes del fix)
- CRM_INGEST_SECRET=<SECRETO ROTADO -- ver WEB-004, valor invalidado y verificado operativamente el 2026-07-24>
```

**Naturaleza del secreto:**
- Mismo valor de 64 caracteres hexadecimales en ambas posiciones
- `CRM_INGEST_SECRET` es el secreto que el landing usa para autenticarse contra el backend
- `PUBLIC_LEADS_INGEST_SECRET` es el secreto que el backend valida al recibir leads
- Ambos son el mismo secreto compartido — deben ser idénticos y rotarse juntos
- El valor estuvo expuesto en el repositorio Git

**Fix aplicado en WEB-003:**
```diff
- PUBLIC_LEADS_INGEST_SECRET=<SECRETO ROTADO -- ver WEB-004, valor invalidado y verificado operativamente el 2026-07-24>
+ PUBLIC_LEADS_INGEST_SECRET=${PUBLIC_LEADS_INGEST_SECRET}

- CRM_INGEST_SECRET=<SECRETO ROTADO -- ver WEB-004, valor invalidado y verificado operativamente el 2026-07-24>
+ CRM_INGEST_SECRET=${CRM_INGEST_SECRET}
```

## Análisis del archivo `proxy.ts`

**Ubicación:** `nexoweb-v2/proxy.ts` (raíz del proyecto)

**Contenido original:**
```typescript
import { NextResponse } from "next/server";
export function proxy() { return NextResponse.next(); }
export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)"],
};
```

**Evidencia de que nunca se ejecutó:**
1. El archivo debe llamarse `middleware.ts` para que Next.js lo reconozca como middleware
2. El export debe llamarse `default` o `middleware`, no `proxy`
3. Cero referencias en todo el codebase (confirmado con grep)
4. Next.js ignora completamente archivos con nombres distintos a `middleware.ts`
